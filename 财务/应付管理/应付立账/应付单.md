
# 功能描述

本功能节点主要提供如下内容：

*  应付单的增删改查以及打印，提供多种录入方式：
 
   *  手工录入；
   *  根据立账依据对应的业务单据单张生成应付单；
   *  根据立账依据对应的业务单据批量生成应付单；
   *  根据发票生成对应的借项通知单、贷项通知单；
   *  外部接口导入；
*  应付单的提交、审核；
*  应付单的挂起、取消挂起；
*  应付单的作废处理；
*  应付单分割、取消分割；
*  应付款的快速付款处理；
*  应付单的各种处理：
 
   *  核销；
   *  调整；
   *  债务转移；
*  预算保留的处理：
 
   *  预算保留；
   *  执行保留；
   *  取消保留；
   *  取消上环节保留；
*  应付单的各种数据查询：
 
   *  未匹配信息；
   *  匹配明细；
   *  余额信息；
   *  核销明细；
   *  针对发票可以查询对应的通知单信息；
   *  针对通知单可以查询对应的发票信息；
   *  挂起明细；
   *  保留执行；
   *  供应商状况。

# 业务规则

*  定义应付单单据类型（必做）
*  定义供应商档案（必做）
*  定义税组合档案（必做）
*  定义立账条件档案
*  定义付款条件档案

# 按钮说明

*  <批量立账>：

本操作用于依据来源单据凭单式立账批量生成应付单，系统会依据所选择的生单条件批量生成，并按分单条件生成多张应付单，支持合单开票或者合行开票。

**操作前提：**有可立账的来源单据。

**操作步骤：**

点击应付管理－>应付立账－>应付单－>批量立账－>批量立应付按钮，可以完成批量立应付；注意：不同采购订单的收货、退货单据同时勾选，且采购参数中严格控制请款为是，则批量立账时会自动做分单处理，退货的单据单独生成借项账户单，对于单头选单的场景，点击【立账】按钮会报错提示。

点击应付管理－>应付立账－>应付单－>批量立账－>批量立费用按钮，可以完成批量立销售费用。

**具体步骤如下所示：**

第1步：点击应付管理－>应付立账－>应付单－>批量立账－>批量立应付/批量立费用按钮，弹出批量立账条件画面；

批量立应付，使用平台的拉单工具，用户可在默认方案的基础上，增加用于过滤的条件和显示的栏目，具体配置方式，详见拉单工具的通用说明。

第2步：在批量立账条件画面输入选单条件；

第3步：点击确定按钮弹出批量立账结果画面，该列表画面列示了可以生成应付单的记录，点击取消按钮放弃本次批量立账；

第4步：在批量立账结果画面点击继续选单按钮返回批量立账条件画面，转回第2步，可以重新输入选单条件；

第5步：在批量立账结果画面的列表记录中勾选本次需要立账的记录，点击确定按钮立账生成应付单，并返回应付单卡片画面，显示生成的应付单，点击取消按钮放弃本次批量立账操作。

*  <执行核销>：

本操作用于将当前应付单与贷方单据即时核销，以减少应付单余额，结清业务，参见：[应用专题－应付核销](http://10.16.9.23/U9C/help/zh-CN/Content/FI/AP/Function/javascript:void(0);)。

**操作前提：**

当前应付单有可处理金额；

当前应付单未作废；

当前应付单已确认立账。

**操作步骤：**点击应付管理－>应付立账－>应付单－>核销按钮，可以完成应付单的即时核销。具体步骤如下所示。

第1步：选择需要核销的应付单，点击核销按钮，弹出应付单处理记账期间画面；

第2步：在弹出的应付单处理记账期间画面中输入核销日期和记账期间，注意：输入的核销日期和记账期间必须大于等于当前应付单的立账日期和记账期间；

第3步：点击确定按钮到第4步，点击取消按钮返回应付单卡片画面；

第4步：进入同币种核销画面，当前应付单根据其单据方向显示在[借方单据列表](http://10.16.9.23/U9C/help/zh-CN/Content/FI/AP/Function/javascript:void(0);)和[贷方单据列表](http://10.16.9.23/U9C/help/zh-CN/Content/FI/AP/Function/javascript:void(0);)中，另一方列表则列示了可以与当前应付单核销的对方单据；

第5步：输入贷方单据列表和借方单据列表的本次核销金额，其中，在输入借方单据列表的本次核销金额后，点击自动分摊可以将输入的借方本次核销金额分摊到贷方单据列表的本次核销金额中，点击清空分摊清空贷方单据列表的本次核销金额；

第6步：点击模拟核销按钮到第7步，点击保存按钮到第8步；

第7步：弹出模拟核销记录列表画面，在模拟核销记录列表画面选择合适的记录，点击确定按钮到第8步，点击取消按钮返回第4步；

第8步：如果系统参数AP102限制付款单转暂付为“否”且有未完全核销的收付款单，则到第9步；否则系统保存并显示本次核销的结果；
