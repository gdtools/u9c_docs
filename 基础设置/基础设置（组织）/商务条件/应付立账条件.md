
# 功能描述

用于定义采购、应付立账过程中何时立账、账期多长的计算规则。

应付立账条件定义后，可在采购订单、收货单、采购合同、应付单中被引用，以用于确定立账日期和账期。

# 关键应用

# 业务规则

*  定义币种档案（可选）
*  应付立账条件编码不允许重复
*  在一个立账条件中，“按固定日期计算”与“月末计算”两种立账日确定方式最多同时只能存在一种。
*  当本画面中的任何一个固定日期不为空时，必须设置此栏目的值。
*  当本画面当前分区的三个固定日期都为空时，才允许设置此栏目的值。
*  当本画面中的任何一个固定日期不为空时，必须设置此栏目的值。
*  当本画面当前分区的三个固定日期都为空时，才允许设置此栏目的值。

U9cloud预置了一些用户常用的日期算法：

1.人工确定：触发立账事务时由用户手工输入具体的日期。

2.交易日：立账日等于触发立账事务的“业务日期”；到期日等于触发立账事务的“业务日期”或立账日。

3.月底：按“月末”规则计算立账/到期日。如月底前3天结，或月底后2天结。

4.固定日：按“固定日”规则计算立账/到期日。如每月25号结帐，则上月26号-本月25号之间的业务在本月25号结，本月26号及以后的业务就规到下月25号去结了。

5.XX天后：按日期偏离规则计算立账/到期日。如收货后3个月结，或发票后15天结。

6.XX天后月底：先按日期偏离规则、再按“月末”规则计算立账/到期日。如，收货45天后的月底结。

7.XX天后固定日：先按日期偏离规则、再按“固定日”规则计算立账/到期日。如，收货2个月后，若在15号前则当月15号结，若在15号后则再下月15号结。

8.上下月：根据跨月类型计算立账/到期日。如25号以后的业务，下月25号再结；25号以前的业务，当天结。

9.上下月月底：先按“跨月”规则、再按“月末”规则计算立账/到期日。如25号以后的业务，下月月底再结；25号以前的业务，当月月底结。

10.上下月固定日：先按“跨月”规则、再按“固定日”规则计算立账/到期日。如25号以后的业务，下月20号再结；25号以前的业务，当月20号结。

11.月底XX天后：先按“月末”规则、再按日期偏离规则计算立账/到期日。如收货当月月底后45天结。

12.固定日XX天后：先按“固定日”规则、再按日期偏离规则计算立账/到期日。如15号前收货，4个月后的15号结；15号后收货，则5个月的15号结。此时固定日规则配成：15号，向前；偏离时间=4个月
