
# 功能描述

用来设置与LRP计算有关的参数。

# 业务规则

*  启用需求计划系统（必做）

# 栏目说明

主界面

|栏目|说明|
|---|---|
|基本页签|
|编号方式|指LRP计算时的计划批号是自动产生还是手工录入。 计划批号用来唯一标识每次LRP运算。在运算结束后可通过计划批号来查找相应的计划订单。 计划批号本身没有任何业务含义。|
|编号规则|自动编号时需要选择一个编号规则。 编号规则在“基础设置-单据编码规则”中维护。系统预制一个计划批号的编码规则。|
|LRP计划订单编码方案|设定计划订单单号的编号规则。编号规则在“基础设置-单据编码规则”中维护。系统预制一个LRP计划订单的编码规则。|
|跟单维度|选择LRP计算时需要的跟单维度，可选择项目、番号、需求分类。该选项可随时修改，影响下次LRP运算结果。|
|计划方案|计划方案用来决定物料的供应方式，及仓库的运算范围。如果有此业务需求，可先定义计划方案后并在此处选择。|
|物料范围|设定LRP计算时的物料范围。可选择专用料、专用料+公用料。|
|LRP时格|如果需要合并产生计划订单，可以选择合并用的时格。|
|考虑替代料|指在LRP运算时，是否考虑替代/替换件做为供应。|
|计算低阶码|指在LRP运算时，是否要先进行低阶码计算后再进行LRP计算。|
|产生投入量为零的计划订单|勾选此选项，表示即使供应满足需求，系统也会产生一笔需求量为零的计划订单。 通过产生为零的计划订单，使计划员能清晰的看到完整的基于BOM结构的计划订单数据，便于核对数据。|
|专用料毛需求|如果勾选，表示对跟单件不考虑任何供应，直接按需求量产生计划订单。否则，系统会先扣除供应后按净需求量产生计划订单。|
|公共料毛需求|如果勾选，表示对公共料不考虑任何供应，直接按需求量产生计划订单。否则，系统会先扣除供应后按净需求量产生计划订单。|
|处理过期需求|过期需求指交期早于当前日期的需求。对这部分需求的供应状况，有的企业是人工管理，而有的企业则让系统来处理。 由于LRP是在上次LRP运算结果基础上，对本次订单需求进行计算。计算时，要优先用供应满足以前运算过的订单需求。通过此选项来控制如果以前运算过的需求为过期需求时，是否还占用供应。勾选此选项，系统只考虑90天以内的过期需求。 勾选此选项时，如果同时指定了LRP时格，则LRP时格的第一个期数应为90天（即过期需求天数），因为此时LRP是从过去的第90天开始划分时格。|
|是否只处理本批需求|如果勾选此选项，表示LRP计算时只会考虑和本次计算有关的需求进行供需平衡。例如：A挂B，B的用量为1。A有一笔销售订单，数量100。B有库存150，B还有一笔备料需求80。现选择A的销售订单进行LRP计算，如果勾选此选项，则系统认为B的需求只有一笔，数量100（即由A的销售订单需求展开的相依需求），B的供应为150。供需比对后，系统认为B的供应足够。如果不勾选此选项，则系统认为B的需求有两笔，数量分别为100（即由A的销售订单需求展开的相依需求）、80（即B的备料需求）。供需比对时，系统会先用库存满足备料需求80，剩余的供应再满足相依需求100。最后，B会产生30（100+80-150）的计划订单。由上例可以看出，在勾选了此选项后，系统并不会考虑本次计算的物料的已有需求对供应的占用，可能会导致供应虚增。所以，该选项通常和毛需求计算配合使用，以实现按“BOM结构”来展算物料需求。计算后往往需要人工根据目前的供应情况来调整计划订单数量。|
|供需来源页签|
|考虑安全库存|指在LRP运算时，是否将安全库存做为需求考虑。 安全库存需求做为公共需求，不记录跟单号信息。|
|考虑负库存|指在LRP运算时，是否将负库存做为需求考虑。 负库存需求产生的计划订单可能会记录跟单号信息。|
|考虑锁定计划订单，考虑生产订单 ，考虑生产线日计划 ，考虑采购合同 ，考虑采购订单，考虑请购单 ，考虑库存在途 ，考虑已入未检数量 ，考虑现存量|用来控制LRP运算时考虑的供应来源。 对毛需求计算，虽然系统用需求量直接产生计划订单，但计划订单上各供应量的数据还是通过勾选各供应来源选项来控制的。所以，毛需求计算时也要勾选这些供应来源选项。 考虑库存在途：指调拨单。 考虑已入未检数量：指存储类型为“待检”、“在检”状态的库存。|
|供应单据状态页签|
|开立/审核中/已审核/开工/完工/挂起|用来控制考虑哪些状态的生产订单、重复计划、请购单、采购订单做为供应。|
|组织范围页签|
|工厂组织，营运组织，组织形态，净需求货主组织方式|用来决定LRP计算的供需组织。即系统只考虑这些组织内的供需数据。具体参考“计划者工作台”功能中的说明。|
|释放页签|
|MO释放时间类型|有三个选项：依开工日期：指计划订单释放工单时，工单的开工日期以计划订单的调整后开始日期为准，并根据提前期正排工单的完工日期。依完工日期：指计划订单释放工单时，工单的完工日期以计划订单的调整后需求日期为准，并根据提前期倒排工单的开工日期。依开完工日期：指计划订单释放工单时，工单的开完工日期均以计划订单为准。|
|过期计划订单释放方式|用来控制过期计划订单能否释放为生产、采购订单。有三个选项：不能释放：指释放过期计划订单时，系统会抛异常。正排：指释放过期计划订单时，将系统当前日期做为业务单据的开始日期，并根据提前期正排完成日期。不处理：指释放过期计划订单时，释放的业务单据也是过期的。|
|采购分单条件，采购分单参数|用来设置释放采购订单时的分单条件。|
|采购合单条件|用来设置释放采购订单时，订单行的合行条件。|
|请购分单条件|用来设置释放请购单时的分单条件。|
|大生产订单分单条件|用来设置释放大生产订单时的分单条件。|
|计划订单维护页签|
|保存时检查料品下发维度|指在计划订单保存时，是否立即检查料品、项目等信息是否已经下发到计划订单的供应组织中。 在多组织的计划产能分流业务中，只有当计划员决定了计划订单在哪个供应组织加工后，才由数据管理部门将相应的物料、项目等基础数据下发到供应组织中。从而避免基础数据过度膨胀及混乱。 即使保存时不检查，在计划订单释放时，系统一定会检查这些基础数据是否已经下发。|
|自动重算计划订单日期|如果勾选，表示在修改了计划订单的开始/完成日期后，系统自动按提前期计算另一个日期。否则，开始、完成日期全部由计划员人工控制。|

# 操作说明

*  通过菜单生产制造－>需求计划－>物料需求计划－>LRP参数设置进入该界面；
*  操作步骤
*  第1步：进入“LRP参数设置”画面。
*  第2步：系统自动加载出所有参数及当前的配置值。
*  第3步：根据需求修改相应参数的值。
*  第4步：点击“保存”按钮。
