
# 功能描述

设置MRP运算时需要的参数值。这些参数会影响MRP运算的结果。具体为：

设置计划名称、版本的默认值，如需求时栅原则、需求时栅天数等。

设置MRP计算用到的参数，如过期需求处理方式、过期需求考虑现存量、单据状态等.

记录历史信息，如最近一次MPS的计划名称等。

设置计划订单释放的参数，如采购分单条件、合行条件、过期计划订单释放方式等。

记录MPS/MRP运算的历史信息。如：最新两次的MPS/MRP运算的计划名称、版本及执行日期。

# 业务规则

*  定义单据编码规则（必做）
*  定义工作日历（必做）

# 栏目说明

计划参数

|栏目|说明|
|---|---|
|编码方案|设置计划订单单号的编码规则。|
|最大低阶码|该参数已废弃。|
|过期需求考虑现存量|指计划运算时，能否使用库存量来满足过期需求。|
|需求时栅原则|设置时界选项的默认值。在计划者工作台中可以修改这些时界选项的值。计划运算是以计划者工作台设置的时界为准。|
|需求时栅天数|
|计划时栅原则|
|计划时栅天数|
|发放时栅天数|
|计划生产订单时栅|
|MO释放时间类型|有三个选项：依开工日期：指计划订单释放工单时，工单的开工日期以计划订单的调整后开始日期为准，并根据提前期正排工单的完工日期。依完工日期：指计划订单释放工单时，工单的完工日期以计划订单的调整后需求日期为准，并根据提前期倒排工单的开工日期。依开完工日期：指计划订单释放工单时，工单的开完工日期均以计划订单为准。|
|时格日期确定原则|时格日期确定原则用来设置时格内计划订单的开始日期如何取值。时格起点类型用来设置划分时格的始点。具体可参考“时格应用专题”中的描述。|
|时格起点类型|
|过期需求处理方式|用来控制为过期需求产生的计划订单是否要进行正向重排：不处理：选择该选项，系统用过期需求的交期做为计划订单的需求日期，并根据提前期计算计划订单的开始日期。则计划订单的开始日期也为过期日期。按当前日期正排：选择该选项，系统对过期需求产生的计划订单，将当前日期做为开始日期，并按提前期计算计划订单的需求日期。则产生的计划订单的开始日期、需求日期都不是过期的日期。|
|过期计划订单释放方式|用来控制过期计划订单能否释放为生产、采购订单。有三个选项：不能释放：指释放过期计划订单时，系统会抛异常。正排：指释放过期计划订单时，将系统当前日期做为业务单据的开始日期，并根据提前期正排完成日期。不处理：指释放过期计划订单时，释放的业务单据也是过期的。|
|过期计划订单确认方式|用来控制如何判断是否为过期计划订单：按开工日期：选择此选项时，当计划订单的开始日期早于当前日期时，系统即认为该计划订单为过期计划订单。按完工日期：选择此选项时，当计划订单的需求日期早于当前日期时，系统即认为该计划订单为过期计划订单。|
|采购件工作日历方式|用来控制是按工作日历还是自然日历来计算采购件计划订单的开始日期。有两个选项：根据供应组织：表示按采购组织的工作日历计算计划订单的开始日期。在计算计划订单开始日期时会扣除工作日历中的休息日。自然日历：表示按自然日历方式计算计划订单的开始日期。 在计算计划订单开始日期时不会扣除工作日历中的休息日。|
|考虑重复件产能|如果勾选，在计划运算时系统对重复件按产线能力进行有限排程，以计算出重复件计划订单的开始日期。如不勾选，系统根据料品档案设置的提前期计算计划订单的开始日期。在重复件计划订单释放时，系统自动按产线能力进行排产，并产生产线日计划。|
|产生采购需求接口数据|在多组织计划运算时，对采购件的净需求，系统除了产生计划订单之外，还会自动产生采购组织的采购需求接口数据。采购组织可以通过采购需求接口数据来采集物料的所有需求信息并集中处理。采购需求接口数据可通过“采购管理-需求接口”功能来查看及编辑。但有时，企业并不需要采购需求接口数据。在这种情况下，通过此选项可避免计划运算自动产生采购需求接口数据。同时也能提高计划运算的性能。|
|是否将货主作为比对纬度|系统在进行供需平衡时，是按照物料的计划维度进行供需匹配的。此选项用来控制货主是否做为计划维度。具体可参考“计划维度应用专题”中的描述。|
|生产计划作为净需求|勾选此选项表示在将生产计划做为计划运算需求时，生产计划的物料不再进行供需平衡，直接根据生产计划的数量产生计划订单。而对子件物料则进行供需平衡，对净需求产生计划订单。对有的企业，生产计划完全是计划人员手工平衡后录入到系统中的，此时无需再让系统进行供需平衡了。但下阶物料还是需要通过系统来进行供需平衡的。|
|自动重算计划订单日期|如果勾选，表示在修改了计划订单的开始/完成日期后，系统自动按提前期计算另一个日期。否则，开始、完成日期全部由计划员人工控制。|
|最近净改变的执行日期|系统自动记录最近两次进行计划运算的计划名称和版本信息。|
|最近执行MRP日期|
|最近执行MPS日期|
|最近执行DRP日期|
|最近执行MPS计划名称.版本|
|上一次MPS计划名称.版本|
|最近执行MRP计划名称.版本|
|上一次MRP计划名称.版本|
|最近执行DRP计划名称.版本|
|上一次DRP计划名称.版本|
|保存时检查料品下发维度|指在计划订单保存时，是否立即检查料品、项目等信息是否已经下发到计划订单的供应组织中。 在多组织的计划产能分流业务中，只有当计划员决定了计划订单在哪个供应组织加工后，才由数据管理部门将相应的物料、项目等基础数据下发到供应组织中。从而避免基础数据过度膨胀及混乱。 即使保存时不检查，在计划订单释放时，系统一定会检查这些基础数据是否已经下发。|
|自动更新用完为止BOM子项|勾选此选项，表示在“替换”业务中，系统会自动计算“旧料”的用完日期，并用该日期更新对应BOM子项的“旧料”的失效日期及“新料”的生效日期。|
|考虑委托方带料需求|在委托/受托加工业务中，通常是委托方组织跑计划来处理委托方带料的需求，受托方跑计划来处理受托方自备料的需求。但有些企业，委托方并不跑计划，此时可通过勾选此选项，让受托方在跑计划时，同时处理委托方带料的需求。|
|计划订单采购转单类型|对采购类型的计划订单，通过此参数来设置计划订单默认的采购类型。|
|负库存补单|设置计划运算时是否将负库存做为需求。|
|重排展望天数|设置当供应日期晚于需求日期多少天之内时，供应可以用来满足需求。具体可参考“重排建议应用专题”中的描述。|

采购分单条件

|栏目|说明|
|---|---|
|采购分单条件|设置计划订单释放采购订单时的采购分单条件。可以按料品、货主组织、需求分类、存储地点、厂牌、项目、任务进行分单。这里设置的是全局的分单 条件，在计划订单释放画面中可针对本次释放的计划订单单独设置采购分单条件。如果没有单独设置，则计划订单释放时按这里设置的分单条件进行处理。|
|分单日期类型|是以计划订单的需求日期还是行动日期来决定计划订单落在哪个时间段内。如果选择“要求交货日”则以计划订单的调整后需求日期为准，如果选择“应下订单日”则以计划订单的调整后行动日期为准。|
|基准日期类型|决定时段划分的始点。可以选择是以当前日期还是计划订单最小需求日期为始点进行划分。|
|时间段|设定按时间维度进行采购分单。通过将整个计划展望期划分为若干时段，不同时段内的计划订单产生相应的采购单据。如时间段=5，表示将整个计划展望期按5天一个时段进行划分。|
|请购分单条件|用来设置计划订单释放请购单时的分单条件。可选择料品、需求分类、项目、番号、采购部门、业务员。其中采购部门、业务员取自料品档案上定义的采购部门和业务员。|

采购合行条件

|栏目|说明|
|---|---|
|采购合行条件|设置计划订单释放采购订单时，采购订单行的合并条件。可选择：不合行、项目、任务、需求分类、番号。物料为固定合行条件无法修改。|
|请购合行条件|设置计划订单释放请购时，请购订单行的合并条件。可选择：不合行、项目、需求分类、番号。|

|生产订单合单条件|设置计划订单释放生产订单时的合并条件。可选择：不合并、项目、需求分类、番号。|

# 操作说明

*  通过菜单生产制造－>需求计划－>物料需求计划－>MRP系统参数设定进入该界面；
*  操作步骤
 
   *  第1步：维护基本页签相关计划参数。
   *  第2步：维护分单条件相关计划参数。
   *  第3步：维护供应单据的状态。
   *  第4步：点击保存。
